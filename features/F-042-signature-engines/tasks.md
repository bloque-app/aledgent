# F-042 — tasks

**The design is ruled (2026-10-25; the rulings are at the end of `plan.md`).** The code follows it. The
tasks `T-042-02` to `T-042-08` land as **one commit each in one pull request** (#71, taken out of draft), small
enough to review one at a time, and each leaves the tree green with every existing test unchanged.
`T-042-09` to `T-042-11` are follow-ups, not in this pull request. No `SPEC.md` change:
`NFR-8` is unchanged. All traces: `NFR-8`, `REQ-SA-8`, `REQ-AR-3`, `REQ-AU-8`, and `REQ-RT-6` for the tasks that
touch the core host.

## Order

`T-042-01` is this document. Then `T-042-02`; `T-042-03` may run beside it. `T-042-04` needs both.
`T-042-05` before `T-042-06`, so that the Transit engine has run against a real Vault before a component
uses it. `T-042-06`, `T-042-07` and `T-042-08` are independent of each other and each needs `T-042-02`.

## Not in this feature

AWS KMS as an engine a component uses directly; the signer service hosting engines; an engine for an operating
system keystore or an HSM; loading engines at run time; batching Transit signatures and measuring the cost; the
settlement adapter's move to native accounts and Ed25519 keys. Each is a feature of its own, and the interface
makes each possible without a change to a component.
