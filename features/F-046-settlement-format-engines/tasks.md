# F-046 — tasks

The design is the plan the owner approved on 2026-11-20. Nothing here changes `SPEC.md`. `T-046-01` to
`T-046-03` come first and change no bytes the adapter signs. The tests (`T-046-07` to `T-046-09`) need the
behaviour from `T-046-04` and `T-046-05`. All of them trace to `REQ-SA-9`.

| ID | Task | Traces | Done when |
|---|---|---|---|
| T-046-01 | **The engine seam.** A format engine in `services/settle/src/chain` owns one format end to end: its extension set (explicit values and implicit data), the `Contracts::call` carrying `execute` for lane batches, anchors and bindings, the signed payload and the extrinsic framing, and the reads whose shape the runtime decides (assets, nonce, block weights, events, `ContractsApi_call`, `TaggedTransactionQueue_validate_transaction`). Today's formats become the first engines, under their current names. The contract's ABI stays shared. The adapter, the fake layer and `RpcChain` choose and sign through the engines, and nothing calls `TxFormat` directly any more | `REQ-SA-9`, `REQ-SA-6` | Every `services/settle` test passes unchanged. Every kreivo-pin vector still agrees byte for byte. A runtime confirmed in `settle_runtimes` before the change is still confirmed after it (same name, no new validation). Every crate that links `settle` (`e2e/aledgent-driver`, `ops`, `conformance`) builds with no change to its code |
| T-046-02 | **The format fingerprint.** It covers the extrinsic version(s) the metadata declares, the transaction extensions in order with the shapes of their explicit and implicit types, and the shapes of the calls submitted. It compares shapes, not registry ids, is sensitive to order throughout, and leaves out `spec_version`. A native engine's fingerprint leaves out `transaction_version`. A PASS engine keeps it while the PASS form exists. The reduced fixtures (`fixtures/surface-*.json`) are re-derived | `REQ-SA-9`, `AC-E4.3`, `AC-E4.4` | Unit tests: a registry renumbered with the same shapes gives the same fingerprint. A reordered field, an extension added with data, a changed extrinsic version and a call argument with a new type each give a different one. Spec 136's metadata matches the spec-133 native engine with no list of `transaction_version`s. The PASS engines' choices on the 132, 133, 134 and 136 fixtures are unchanged |
| T-046-03 | **Dynamic encoding.** Engines encode the `Contracts::call` arguments and each transaction extension through subxt's dynamic API from live metadata (`subxt::dynamic::tx`, extensions by identifier). They hand-write only the values the adapter chooses, the PASS message order while that form exists, and the contract's ABI. An extension the engine does not know that carries data means the engine does not fit. The positional encoder is removed wherever the dynamic one covers it | `REQ-SA-9`, `REQ-SA-6` | For every pinned vector the dynamic bytes equal Kreivo's crates' bytes, for both payload lengths (under and over 256 bytes) and for withdrawal batches and anchors alike. The fake layer decodes and authorises them. Nothing hand-written remains that the metadata describes |
| T-046-04 | **The switch at the first finalized block under the new runtime.** The runtime a transaction is signed for, and the engine chosen for it, are read at the finalized head. While the best head's runtime differs from the finalized head's, nothing new is signed, and stored, uncertain transactions are still broadcast again. The confirmation (`F-027` decisions 47 and 51) runs at that finalized block. The operator's mapping (`adapter.formats`) names an engine and is still confirmed | `REQ-SA-9`, `REQ-SL-4`, `REQ-SO-7` | Fake-layer tests: an upgrade at the best head that is not yet final signs nothing new. Once it is final, the first transaction in the new engine is validated before it is broadcast. An upgrade reorganised away before finality is never signed for. An upgrade that keeps the fingerprint keeps serving with no release or configuration once it is final (`AC-E4.3`). A mapped `spec_version` is served only after the layer confirms it |
| T-046-05 | **No engine fits: refuse and alert.** `Refusing::UnknownSurface` stays as it is. The adapter also raises `format:<spec_version>`, naming the fingerprint's parts that differ from the closest engine, and writes it only under the lease. `AledgentAdapterNoFormat` pages on it with no `for`. The alert clears when an engine fits (a new release) or the runtime changes again | `REQ-SA-9`, `AC-E4.4`, `NFR-11` | Tests: a runtime with no engine is refused at once. Nothing is signed or broadcast for it, the adapter declares that it does not serve, and the alert opens with the parts that differ. A release with the engine clears the alert and serves after the confirmation. `ops`' alert test pages for kind `format` |
| T-046-06 | **The check before enactment, and its runbook.** `aledgent-settle <config> formats <metadata>` reads a candidate runtime's metadata file (SCALE `RuntimeMetadataPrefixed`) and prints its fingerprint and the engine that fits, or the parts no engine covers. It exits non-zero if none fits, and it opens no layer, store, key or ingress. `ops/runbooks/release/kreivo-runtime-upgrade.md`: watch the referendum, take the candidate's metadata from a fork with the upgrade applied, run the check, ship the release before enactment, rehearse the confirmation on the fork, and watch the switch and the alert at enactment. No operator's accounts or hosts appear in it | `REQ-SA-9`, `NFR-11` | Tests on the 132, 133, 134 and 136 fixtures and on a doctored one (an extension added): the engine named, or a non-zero exit with the parts named. The runbook is linked from `settlement-adapter-outage.md` and passes the repository's licence check |
| T-046-07 | **Conformance vectors per engine.** Each engine has its own vectors (native, both payload lengths, a withdrawal batch and an anchor) in the kreivo-pin workspace for the Kreivo revisions it is pinned to. Each vector is checked with Kreivo's own types (`UncheckedExtrinsic` decoded, the signature verified over the payload that `check` builds). A new engine ships with its workspace and its CI job, as `kreivo-pin-136` did | `REQ-SA-9`, `REQ-SA-6` | One CI job per pinned workspace, all green. `services/settle` pins its own engines to the same vector files. Removing an engine's vectors fails CI |
| T-046-08 | **Zombienet: a runtime upgrade N → N+1 mid-run.** A job in `e2e-zombienet.yml` builds two Kreivo releases whose fingerprints differ (spec 132's `0.16.9` to a release with spec 133's surface, the change mainnet made in 2026-10). It enacts the upgrade through the network's root origin while withdrawals are in every state: acknowledged and unsigned, signed and stored but not broadcast, broadcast and uncertain. One variant runs a release with no engine for N+1, which refuses and alerts, then starts the release that has the engine. Another variant runs an upgrade that keeps the fingerprint | `REQ-SA-9`, `REQ-SO-7`, `REQ-SL-4`, `AC-E4.3`, `AC-E4.4` | Every withdrawal ends `Settled`, or `Released` on both proofs (the inbox and the unconsumed nonce). No operation has a second transaction. The first transaction under N+1 is validated before it is broadcast, at the first finalized block under N+1. The variant with no engine refuses at once with `format:<spec_version>` and serves once the new release starts. The unchanged variant serves throughout with no release. The suite's checks pass over the final state |
| T-046-09 | **A redeploy across the upgrade.** The adapter is stopped mid-batch at each `CrashPoint` while N is enacted to N+1, and the release with N+1's engine is started on the same store | `REQ-SO-7`, `REQ-SA-6`, `REQ-SL-4`, `AC-E4.4` | Fake layer, at every crash point: stored bytes are broadcast again, never re-signed. Those N+1 rejects end `EraEnded` and are released at expiry on both proofs. What can no longer be signed within its expiry is tombstoned (`NeverSigned`) and released, with the full amount back as available. The rest are signed in the new engine after the confirmation. No operation has a second transaction. Zombienet does the same at `after-persist` and `after-broadcast` (`ALEDGENT_SETTLE_CRASH_AT`) |
