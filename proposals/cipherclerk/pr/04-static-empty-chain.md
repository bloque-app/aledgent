# perf(merkle): the empty-subtree chain as a static table

**Depends on #1.** This branch is cut from #1's branch (`rng-as-parameter`), so until #1 merges its diff
also shows #1's commit. The change of this PR is its last two commits: `perf(merkle): the empty-subtree
chain as a static table` and a style commit. They use nothing #1 adds; they sit on #1 because that is the
base we measured and the one our guest builds.

`build_empty_chain()` recomputes the 129 empty-subtree hashes, 128 BLAKE2b calls, every time a sparse
Merkle root, proof, batch proof or state root is computed. The chain is a constant of the tree's
definition, so this PR makes it a static table that every caller borrows. **Roots and proofs do not
change.**

## Problem

At `e9a7b08`, `SparseMerkleTree::root`, `SparseMerkleTree::prove`, `BatchProof::build`,
`BatchProof::root` and `state_root::composite_state_root` each call `build_empty_chain()`, which hashes
128 times and returns the 4 KiB table by value. `empty_subtree_hash(d)` builds the whole chain to read one
entry. In a VOS PVM guest, one reservation in our ledger's core does 14 of these rebuilds: 1 792 hashes,
21 % of its 8 470, at about 16 k gas each.

## Change

Two commits, 2 files, +820 −24; almost all of the added lines are the table (129 rows of 32 bytes, as
`cargo fmt` wraps them).

- **`src/merkle.rs`.**
  - `pub static SMT_EMPTY_CHAIN: [[u8; 32]; SMT_DEPTH + 1]`: the chain, `[0] = SMT_EMPTY_LEAF` and
    `[d] = smt_node_hash([d-1], [d-1])`, one commented row a depth.
  - `pub fn compute_empty_chain()`: the recurrence, as `build_empty_chain()` computed it before.
  - `build_empty_chain()` keeps its signature and returns a copy of the table, for existing callers.
  - `empty_subtree_hash`, `SparseMerkleTree::{root, prove}` and `BatchProof::{build, root}` borrow the
    table.
  - A test, `the_static_empty_chain_is_the_recurrence`, holds the table and `build_empty_chain()` to
    `compute_empty_chain()`.
- **`src/state_root.rs`.** `composite_state_root` borrows the table, and so does its test.
- **The style commit.** `cargo fmt` wraps each 32-byte row over four lines, and the callers pass the
  borrowed table on as is rather than as `&&` (clippy's `needless_borrow`, twelve places).

## Design choices and alternatives

- **A static table, not a lazily computed one.** A `once_cell` or `spin::Once` would need a dependency or
  `std` and still hash 128 times in each fresh guest invocation. A `const fn` would need BLAKE2b in
  `const` context. The literal table costs 4 KiB of read-only data and nothing at run time, and the test
  makes a wrong row impossible to miss.
- **Keep `build_empty_chain()`**, so no caller breaks; new code borrows `SMT_EMPTY_CHAIN`.

## Measured

Actor gas per reservation in our core, on the VOS-native runtime, one change at a time:

| Patch | Actor gas per reservation |
|---|---:|
| before | 293.5 M |
| **this PR** | **256.5 M (−12.6 %)** |
| #3, VOS's BLAKE2b | 227.5 M (−22.5 %) |
| #3 and this PR | 204.4 M (−30.4 %) |
| and #5, with VOS's native curve calls | 154.0 M |
| and the guest at `opt-level = 3` (our build) | 104.8 M (−64 %) |

On one hosted runner (AMD EPYC 7763), at batch 128 under the Agent's 8 G limits, the core goes from 15.5
to 17.8 reservations a second with this PR alone, and to 26.5 with #3 too. Gas is exact and the same on
every machine. Native callers gain too, since every root and proof skips 128 hashes.

## Compatibility

- **No change in any root, proof or wire format.** The table is the recurrence's output, checked by the
  test.
- **API: additions only** (`SMT_EMPTY_CHAIN`, `compute_empty_chain`). `build_empty_chain()` and
  `empty_subtree_hash()` keep their signatures and results.

## Why we need it

We are building a confidential double-entry ledger that runs as a VOS Agent and decides each
balance-affecting command inside the guest, within a completion budget. Its throughput there is bound by
gas, and a fifth of its hashing was this one constant, recomputed.
